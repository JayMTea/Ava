# Ava core runtime — bridge (web app + API + dashboard) + inference router.
# Pinned to the versions this project runs on. Install:  pip install -r requirements.txt
# Optional extras: voice/STT -> requirements-voice.txt (Piper TTS is a vendored
# binary under bin/piper/); dev/tests -> requirements-dev.txt.
# NOTE: fastapi 0.138.x + starlette 1.3.x silently drop every route on a
# prefixed APIRouter (breaks the whole /api/hub/* Hub API on include_router).
# FASTAPI is what stays pinned for that reason; starlette 1.3.1 is fine WITH
# 0.136.3, which is not obvious and was measured rather than assumed. Verify
# before bumping either:
#   APIRouter(prefix="/x") + a route must still resolve after app.include_router().
#
# starlette 1.2.1 -> 1.3.1 on 2026-07-31, for two advisories that both land on
# code Ava actually runs: request.form() limits silently ignored for
# application/x-www-form-urlencoded (GHSA, high — /login and /setup are public
# and take form bodies), and an unvalidated request path concatenated into the
# authority when request.url is reconstructed (low — but auth_gate classifies
# EVERY request from request.url.path, so a poisoned reconstruction is an
# auth-gate question, not a cosmetic one).
#
# Verified before bumping, on a throwaway venv with fastapi held at 0.136.3:
#   * APIRouter(prefix="/x") -> GET /x/ping returns 200 (the check above)
#   * 1265 passed, 7 skipped
#   * a real bridge boots; /api/hub/{system,persona,memory,models,cost,
#     connectors} all 200, and openapi paths == 148 — byte-identical to the
#     same probe on 1.2.1, including which paths 404 (agent/voice/governance
#     have no bare GET, on both versions).
fastapi==0.136.3
uvicorn[standard]==0.52.0
starlette==1.3.1
# The agent runtime talks to the OpenClaw gateway over a WebSocket
# (ava_bridge/runtime/openclaw_gw_client.py), and the /apps/<id> websocket proxy
# dials upstream with the same library. Same story as Pillow, trafilatura and
# huggingface_hub below: it is already present here, because uvicorn[standard]
# pulls it in transitively — which is exactly how those three broke a fresh
# clone while working fine on the maintainer's box. uvicorn's extra is an
# implementation detail of the SERVER; Ava now imports the library directly, so
# it declares it directly.
websockets==16.0
requests==2.34.2
# [socks] is load-bearing, not cosmetic: web search/fetch default to Tor
# (config.WEB_TOR_SOCKS = socks5h://127.0.0.1:9050) and httpx only gains a SOCKS
# transport via this extra. Bare `httpx` raised ImportError at client
# construction — matched by none of web.py's handlers, so it surfaced as a
# generic 502 and a headline capability was dead on every fresh clone. It worked
# here only because socksio arrived transitively.
httpx[socks]==0.28.1
PyYAML==6.0.3
python-multipart==0.0.32
numpy==2.5.1
anthropic==0.120.2
# Hardware abstraction layer (ava_bridge/hwinfo.py): psutil reads system/unified
# memory + CPU natively across macOS/Linux/Windows. nvidia-ml-py (NVML) is the
# native NVIDIA telemetry API; it's import-guarded and simply inactive on non-
# NVIDIA hosts (Apple Silicon, CPU-only), which fall back to psutil + shell.
psutil==7.2.2
nvidia-ml-py==13.610.43
# Brand-asset ingest (ava_bridge/brand.py, ava_bridge/brand_pack.py). Undeclared
# until 2026-07-28: it was installed transitively on the maintainer's box, so a
# fresh clone never got it. `ingest_asset` imports it unguarded on purpose — the
# RE-ENCODE is the security step there (the bytes written are bytes Pillow
# produced, which is what strips EXIF and appended-payload polyglots), so
# Setup -> Branding must fail loudly rather than quietly skip it.
Pillow==12.3.0
# Article extraction for web_fetch (ava_bridge/web.py). Same story as Pillow:
# present here, declared nowhere. Its absence is caught by a best-effort
# `except`, so a fork silently fell back to crude tag-stripping — web_fetch kept
# "working" while handing Ava markup soup instead of clean markdown.
trafilatura==2.2.0
# The model downloader (`ava models pull`). Same story again: `_pull_hf` shells
# out to the `hf` binary, which only exists if huggingface_hub[cli] is installed
# — it was, transitively, on the maintainer's box. On a fresh clone the very
# first documented step after `ava setup` printed "huggingface CLI not found"
# and no weights ever arrived, so chat had nothing to serve.
#
# No `[cli]` extra: that was a 0.x thing. Since 1.0 the `hf` console script
# ships in the base package, and asking for a nonexistent extra only earns a
# pip warning.
huggingface_hub==1.26.0
