# Ava GPU voice extras — OPTIONAL, opt-in. Powers the natural-voice TTS (Kokoro)
# and fast STT (Whisper) that run in a SEPARATE GPU sidecar (kokoro_tts.py), not
# the main bridge. Voice works without these: it defaults to CPU (Piper TTS +
# faster-whisper STT from requirements-voice.txt) and only uses the GPU path when
# you run deploy/gpu-voice-serve.sh AND set AVA_TTS=kokoro / AVA_STT=gpu in the
# bridge env. If the sidecar is down, the bridge transparently falls back to CPU.
#
# Needs a CUDA-enabled PyTorch already importable. deploy/gpu-voice-serve.sh
# builds the sidecar venv with --system-site-packages so it inherits the host's
# CUDA torch (the same one that serves the model). On a fresh host, install the
# matching torch first, e.g.:
#   pip install torch --index-url https://download.pytorch.org/whl/cu124
#
# Install:  bash deploy/gpu-voice-serve.sh   (creates .venv-tts + installs these)
# PINNED, with the evidence for each pin stated. Unpinned lines here meant the
# sidecar resolved differently on every install, and `transformers>=5.15.0` was a
# FLOOR ABOVE what any machine here has (5.12.1) — so this file, as written, had
# never been installed successfully either.
#
# kokoro/soundfile: recorded from the working .venv-tts on the maintainer's box.
# fastapi/uvicorn: deliberately the SAME pins as requirements.txt, so the sidecar
#   and the bridge cannot drift onto two different versions of the same server.
# transformers/accelerate: floors, not exact pins — the sidecar venv is built with
#   --system-site-packages (deploy/gpu-voice-serve.sh) so it inherits whatever CUDA
#   torch stack the host already has, and pinning an exact transformers here would
#   fight that. The floor is the lowest version confirmed to import with kokoro
#   0.9.4; raise it only after checking on a real CUDA box.
kokoro==0.9.4
soundfile==0.14.0
transformers>=5.15.0
accelerate>=1.14.0
fastapi==0.136.3
uvicorn[standard]==0.52.3
