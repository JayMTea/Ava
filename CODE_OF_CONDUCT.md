# Code of Conduct

## The short version

Be decent. Assume the other person is trying to help. Ava is maintained by one
person in their spare time, so patience is a two-way obligation: don't demand,
and don't berate someone for a slow reply.

## What's expected

- Keep criticism about the work, not the person. "This breaks on AMD because X"
  is useful; "this is amateur" is not.
- Accept that "no" is a legitimate answer. Scope discipline is why this project
  can be maintained at all, and a declined feature isn't a slight.
- Report what you actually observed. A fabricated or exaggerated reproduction
  wastes the scarcest resource here, which is maintainer time.
- Respect the privacy posture. Don't post someone else's logs, chat contents,
  screenshots, or voice data in an issue, and scrub your own before pasting.

## What isn't acceptable

Harassment, discriminatory language, sexualised attention toward anyone here in
that capacity, sustained disruption, deliberately misleading reports, publishing
private information, or using the issue tracker to pressure someone personally.

Note that Ava can be configured to generate adult content on a user's own
hardware. That is a private capability of a self-hosted tool; this project's
public spaces are not a venue for it. Do not post such material in issues,
discussions, or pull requests.

## Scope

This applies in every project space — issues, pull requests, discussions, commit
messages, code review — and to any conduct elsewhere that would make people
unsafe participating here.

## Enforcement

Report a problem to the maintainer at the address in
[SECURITY.md](SECURITY.md); mark it as a conduct issue rather than a
vulnerability. Reports stay private.

Responses, roughly in order: a private word, an edit or deletion, a warning, a
temporary block, a permanent block. A single serious incident can go straight to
the end of that list. As a solo maintainer I can't promise a response time —
I can promise that reports are read and not left to rot.
