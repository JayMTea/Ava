# Ava trademark policy

**The short version: the code is yours, the name is not.**

Ava's source is [Apache-2.0](LICENSE). Fork it, modify it, sell it, run it for
other people - all fine, and none of it needs permission. Apache-2.0 §6 is
explicit that it grants **no trademark rights**, and this page says what that
means in practice so nobody has to guess.

This is not a restriction on what you can build. It is the ordinary line every
open project draws between *the software*, which is free, and *the name someone
attaches their reputation to*, which cannot be - because if two different things
are both called Ava, "I use Ava" stops meaning anything, and the person harmed is
whoever downloaded the wrong one.

---

## What is covered

The name **Ava** as it refers to this project, and the Ava logo and wordmark.

Note that the name is also a normal given name and a common word in other
contexts. Nothing here reaches beyond this project's software; if your product
is unrelated, this page has nothing to do with you.

---

## You do not need to ask for any of this

- **Using Ava**, personally or commercially, at any scale.
- **Forking, modifying and redistributing** it, including for money.
- **Running it as a service** for other people.
- **Saying what is true**: "built on Ava", "a fork of Ava", "compatible with
  Ava", "Ava-based". Nominative use - naming the thing you actually built on -
  is exactly what trademark law leaves open, and it is welcome here.
- **Re-branding your own install.** Ava ships a branding system that changes the
  name, colour, logo and icons of your instance - see
  [docs/BRANDING.md](docs/BRANDING.md). It costs nothing, it is not gated, and it
  is not a trademark question at all. An install that calls itself Northwind *is*
  Northwind.
- **Writing about it**, screenshotting it, teaching it, packaging it for a distro.

## Please ask first for

- Naming a **fork or a product** in a way that reads as this project: "Ava Pro",
  "Ava Cloud", "Ava Enterprise", `ava-something` as your product's own name, or a
  domain of the same shape.
- Using the **logo or wordmark** as the mark of your own product or company.
- Anything that could reasonably lead someone to believe your project **is** this
  one, is endorsed by it, or is its official hosted version.

Ask via a GitHub issue on [JayMTea/Ava](https://github.com/JayMTea/Ava) or
through the contact links in [NOTICE](NOTICE). The answer is usually yes, and
usually quick - the point of this page is to be asked, not to say no.

---

## The one thing that is not okay

Presenting a modified Ava **as** Ava.

If you change how it behaves, what it sends, where it sends it, or what it does
with someone's data, users need to be able to tell it apart from what this project
publishes. That is the whole substance of the policy, and it is a *user
protection*, not an ownership claim: a fork that quietly ships a different privacy
posture under the same name spends trust it did not earn - and the person who
pays for that is not the maintainer, it is whoever installed it.

The [branding system](docs/BRANDING.md) makes doing the right thing trivially
easy: change the name, upload your own mark, and there is nothing left to be
confused about.

## Not covered by this page

- **Your own brand assets.** A logo you upload into your install is yours. It
  never leaves your machine, and nothing in this project claims anything about it.
- **Third-party marks.** NVIDIA, vLLM, Ollama and every model vendor own
  their own names; see [NOTICE](NOTICE).
- **The code.** Every question about the software itself is answered by
  [LICENSE](LICENSE), not by this file.
